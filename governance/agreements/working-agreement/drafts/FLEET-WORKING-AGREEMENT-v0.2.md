**The contract.** Shane defines outcomes, authorizes meaningful work, and accepts consequential results. Agents claim bounded tasks, work them where the task says, and show evidence. A validator who is not the executor confirms consequential work before it is Done. Work that exists only in a chat, a mailbox, or a home directory has not been delivered.

## Surfaces

- **Linear** (the active Fleet team — today `FLEET`; if work moves to `FEET`, this agreement moves with it): what work exists, who has it, its state, and decisions.
- **GitHub** (workslo): code, branches, PRs, checks. GitHub proves execution; Linear records the agreement about it.
- Everything else — chat, AgentMail, local files, dashboards — supports the record and never replaces it. A decision made elsewhere binds once it lands on the issue.

## Lifecycle — Linear's stock states, six rules

| Step | State | Rule |
|---|---|---|
| Create | Backlog / Todo | Anyone may file an issue. Shane's comment or edit on it is the authorization for meaningful work — no separate proposal form. |
| Claim | delegate set + a comment | The executor says so on the issue. Silence is not acceptance, and a name typed into a field is not a claim. One accountable executor per task. |
| Track | In Progress | Comment on material events: started, blocked, forecast changed, submitted. A blocker comment names what is blocked and what decision or dependency unblocks it. |
| Validate | In Review | The executor posts a completion comment — what changed, with evidence links (PR, commits, test output). For consequential work, someone other than the executor checks it; returned work goes back to the executor. |
| Complete | Done | Only after validation. An idle runtime, a dead session, or an exhausted budget never makes anything Done. Shane accepts before Done when the outcome touches money, production, other people, or an external commitment. |
| Exit | Canceled | Work untouched for 30 days is canceled, with a note saying why. Handing work back is fine: comment, clear the claim, and the owner reassigns. |

A task's issue is its contract: deliverable, executor, scope limit, acceptance evidence, next action or wake trigger, source. Six lines, in the description.

## Shane always decides

New meaningful projects; material changes to scope, priority, cost, or risk; new credentials or access changes; purchases and external commitments; destructive operations; merge, deploy, publish, and outbound messages — unless the issue itself grants that authority, naming the action and its limit. Delegation passes work, never authority the delegator lacks.

## Working rules

- Every agent has its own Linear app and GitHub app, and posts only under that app. No working app yet: contact Shane — never post as him.
- Parallel edits to the same files go in separate worktrees.
- A new session or harness is not a new agent; continuity lives in the records above, not in context.
